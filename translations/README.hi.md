## यह क्या है?

Agent-Vorcl-Flow एक समर्थित कोडिंग एजेंट को **संरचित इंजीनियरिंग टीम** में बदल देता है। एक सामान्य सहायक के बजाय, आपको **24 केंद्रित उप-एजेंट** (वास्तुकार, कोड-ग्राउंडेड प्रिंसिपल आर्किटेक्ट, बैकएंड, फ्रंटएंड, Expo मोबाइल इंजीनियर, उत्पाद और विज़ुअल डिज़ाइन इंजीनियर, DB इंजीनियर, आर्किटेक्चर कार्टोग्राफर, लाइवबोर्ड ऑपरेटर, और अधिक) मिलते हैं, प्रत्येक का अपना डोमेन **कौशल**, त्वरित **स्लैश कमांड**, और **MCP उपकरण** होते हैं जिनकी उसे आवश्यकता होती है। प्रत्येक गैर-तुच्छ कार्य एक अनुशासित **Task Master** लूप के माध्यम से चलता है - *लक्ष्य → कार्य → कार्यान्वयन → सत्यापित → किया गया* - इसलिए कार्य की योजना बनाई जाती है, ट्रैक किया जाता है, और रुकावटों से बचा जाता है।

- 🧩 **24 उप-एजेंट**, 46 कौशल, 150 स्लैश कमांड
- ⚡ **एक-कमांड इंस्टॉल** Claude Code, Codex, Cursor, और/या Kimi CLI के लिए - `npx`
- 🔌 **11 MCP सर्वर** (GitHub, Postgres, MongoDB, Redis, Docker, Firecrawl, Vercel, रेंडर, फ़ाइल सिस्टम, Task Master, Mermaid) में वायर्ड
- 🔑 **सभी रनटाइम के लिए एक `.env` फ़ाइल** — कुंजियाँ लॉन्चर द्वारा पढ़ी जाती हैं, `~/.zshrc` नहीं, इसलिए वे GUI/IDE लॉन्च से भी काम करती हैं; कोई दूरस्थ AVF सेवा नहीं; लाइवबोर्ड केवल लोकलहोस्ट और अल्पकालिक है
- 🤝 **एक ही स्रोत से Claude Code, GPT Codex, Cursor, और Kimi CLI** पर चलता है

## त्वरित शुरुआत

### आवश्यकताएँ
- **Node.js ≥18**
- **[Claude Code](https://claude.com/claude-code)**, **[GPT Codex](https://developers.openai.com/codex/cli/)**, **[Cursor](https://cursor.com/)**, और/या **[Kimi CLI](https://github.com/MoonshotAI/kimi-cli)**

### इंस्टॉल करें (एक कमांड)

```bash
# Installs adapters for Claude Code, Codex, Cursor, and Kimi CLI:
npx github:Vitammiin/agent-vorcl-flow
```

ध्वज के साथ एकल रनटाइम को लक्षित करें:

```bash
npx github:Vitammiin/agent-vorcl-flow --claude   # Claude Code only
npx github:Vitammiin/agent-vorcl-flow --codex    # GPT Codex only
npx github:Vitammiin/agent-vorcl-flow --cursor   # Cursor only
npx github:Vitammiin/agent-vorcl-flow --kimi     # Kimi CLI only
```

इंस्टॉलर क्या करता है:

| रनटाइम | कार्रवाई |
| --- | --- |
| **साझा परत** | लॉन्चर को `~/.config/agent-vorcl-flow/bin/mcp-env.mjs` में कॉपी करता है और टेम्पलेट से `~/.config/agent-vorcl-flow/.env` बनाता है (एक बार) - प्रत्येक रनटाइम के लिए एकल कुंजी फ़ाइल। |
| **Claude Code** | इस रेपो को एक प्लगइन **मार्केटप्लेस** के रूप में पंजीकृत करता है और प्लगइन को सक्षम करता है (`claude plugin …` के माध्यम से, सीधे `~/.claude/settings.json` फ़ॉलबैक के साथ)। |
| **GPT Codex** | कौशलों को `~/.agents/skills` में और `config.toml` + `AGENTS.md` ब्लॉक को `~/.codex` (इमपोटेंट, मार्करों के बीच) में विलीन कर देता है। |
| **Cursor** | `~/.cursor/skills` में कौशल स्थापित करता है, `~/.cursor/agents` में मूल कस्टम सबएजेंट स्थापित करता है, और लापता सर्वरों को `~/.cursor/mcp.json` में मर्ज करता है। |
| **Kimi CLI** | `~/.kimi/skills` में कौशल स्थापित करता है, `~/.kimi/agents` में मूल Expo कस्टम एजेंट, दोनों Expo आर्किटेक्चर/UI हुक `~/.kimi/config.toml` में स्थापित करता है, और MCP सर्वर को मर्ज करता है। |

> इंस्टॉलर कभी भी आपके रहस्य नहीं भरता - यह केवल टेम्पलेट से एक खाली `.env` बनाता है। आप वहां कुंजियाँ जोड़ें (देखें [Configuration](#कॉन्फ़िगरेशन-mcp-और-कुंजियाँ))।

### नवीनतम संस्करण में अपडेट करें

npm `latest` टैग के साथ इंस्टॉलर को फिर से चलाएँ:

```bash
npx --yes agent-vorcl-flow@latest
```

केवल एक रनटाइम को अपडेट करने के लिए, वही रनटाइम फ़्लैग रखें जिसका उपयोग आपने इंस्टॉलेशन के दौरान किया था:

```bash
npx --yes agent-vorcl-flow@latest --claude
npx --yes agent-vorcl-flow@latest --codex
npx --yes agent-vorcl-flow@latest --cursor
npx --yes agent-vorcl-flow@latest --kimi
```

अद्यतन Agent-Vorcl-Flow-प्रबंधित कौशल, एजेंट, हुक, लॉन्चर और कॉन्फ़िगरेशन ब्लॉक को ओवरले करता है। यह आपके मौजूदा `~/.config/agent-vorcl-flow/.env` और उसके रहस्यों को अपरिवर्तित रखता है, और अपस्ट्रीम Firecrawl कौशल को संरक्षित रखता है। अद्यतन कोडिंग क्लाइंट को बाद में पुनः प्रारंभ करें (या `/reload-plugins` को Claude Code में चलाएँ)।

### वैकल्पिक इंस्टॉल (Claude Code)

```bash
# Load for the current session only (great for trying it out):
claude --plugin-dir /path/to/agent-vorcl-flow

# Or install persistently from a local marketplace:
/plugin marketplace add /path/to/agent-vorcl-flow
/plugin install agent-vorcl-flow
```

इंस्टॉल करने के बाद, एजेंटों को लोड करने के लिए **पुनः आरंभ करें Claude Code** (या खुले सत्र में `/reload-plugins` चलाएँ)।

## कैसे उपयोग करें

इस अनुभाग के उदाहरण Claude Code वाक्यविन्यास का उपयोग करते हैं; उनके मूल सिंटैक्स के लिए नीचे [Cursor](#cursor) और [GPT Codex](#gpt-codex) मैपिंग देखें। Claude Code में टीम को आमंत्रित करने के **तीन तरीके** हैं।

### 1. सार्वभौमिक प्रवेश बिंदु - बस एक लक्ष्य बताएं
```text
/vorcl add a shopping cart to checkout
/audit .
```
`/vorcl` यह पता लगाता है कि किस उप-एजेंट को काम का मालिक होना चाहिए और पूरा Task Master चक्र चलाना चाहिए। `/audit` बैकएंड, फ्रंटएंड, मोबाइल, डेटा और बुनियादी ढांचे का स्वतः पता लगाता है और सभी प्रासंगिक भूमिकाओं का उपयोग करके साक्ष्य-आधारित `PROJECT_AUDIT.md` लिखता है।

### 2. किसी विशिष्ट उप-एजेंट से बात करें
```text
@agent-vorcl-flow:architect  design billing for a SaaS
@agent-vorcl-flow:backend    add a POST /invoices endpoint
```

### 3. एक विशिष्ट स्लैश कमांड चलाएँ
```text
/backend:create-api   POST /invoices
/analyzer:audit       src/
/screenshot:convert   ./mockups/dashboard.png  react
```

प्रत्येक एजेंट का अपना `/<agent>:vorcl` प्रवेश बिंदु भी होता है जो उस एजेंट के दायरे में आने वाले Task Master लूप को चलाता है।

### द Task Master लूप
प्रत्येक गैर-तुच्छ कार्य **Task Master** (`task-master-ai`) से होकर गुजरता है:

```text
goal → tasks (parse_prd / add_task) → next_task → get_task → expand_task
     → implement → verify (testStrategy) → set_task_status done
```इससे काम नियोजित, जांच-पड़ताल और फिर से शुरू करने योग्य रहता है - सत्यापन चरण को पार किए बिना कुछ भी "पूरा" घोषित नहीं किया जाता है।

**जानने लायक कुछ बातें:**
- **फ्रंटएंड हमेशा वास्तविक API से बात करता है।** बैकएंड का OpenAPI स्पेक सत्य का एकल स्रोत है; इससे (`openapi-typescript` + `openapi-fetch`) प्रकार उत्पन्न होते हैं। उत्पादन पथ में कोई नकल नहीं.
- **`database` म्यूटेशन के लिए स्पष्ट पुष्टि की आवश्यकता होती है।** एनालिटिक्स केवल पढ़ने के लिए हैं; स्कीमा/डेटा परिवर्तन (डीडीएल/डीएमएल/माइग्रेशन) आपकी अनुमति के बिना कभी नहीं चलते।
- **`resilience` एक सुरक्षा हुक भेजता है।** एक गैर-अवरुद्ध `PostToolUse` हुक (`catch-guard.js`) आपके द्वारा अभी-अभी संपादित फ़ाइलों में खाली `catch {}` ब्लॉकों को धीरे से चिह्नित करता है।
- **`archmap` कभी भी कल्पना से नहीं निकलता।** निष्कर्षण और प्रतिपादन को सख्ती से अलग किया जाता है: शून्य-निर्भरता स्क्रिप्ट रेपो को `architecture.json` (वास्तविक एफके कार्डिनैलिटी वाले डेटाबेस, API रूट, एआई एजेंट अपने मॉडल/टूल्स/मेमोरी, आयात ग्राफ़, एनवी) के साथ चलाती हैं, और प्रत्येक आरेख केवल उसी JSON से प्रस्तुत किया जाता है। एलएलएम सत्यापन योग्य `file:line` के बिना जो कुछ भी जोड़ता है उसे बलपूर्वक चिह्नित `inferred:true` किया जाता है और धराशायी कर दिया जाता है।
- ** पूर्ण आर्किटेक्चर प्रकाशन वर्कफ़्लो है। ** यह एजेंट को लॉन्च करने वाले किसी भी रिपॉजिटरी में काम करता है, टोपोलॉजी साक्ष्य के रूप में मार्कडाउन दावों को अनदेखा करता है, टीएस / जेएस, पायथन, गो, जावा, सी #, रस्ट, पीएचपी, रूबी, कोटलिन और स्विफ्ट के लिए बंडल ऑफ़लाइन ट्री-सिटर WASM का उपयोग करता है, पहले `ARCHITECTURE.md` लिखता है, फिर साझा JSON मॉडल, स्व-निहित HTML, PDF, देशी ड्रॉ.io और तैयार करता है। प्रतिलिपि योग्य Mermaid L0–L4. `update` पूर्ण पुन: स्कैन करता है और एनोटेशन और अप्रबंधित फ़ाइलों को संरक्षित करता है।
- **ढूंढता है, बनाता कभी नहीं।** एक चल रहे ऐप के स्क्रीनशॉट को देखते हुए, यह स्क्रीन को वास्तविक कोड - घटक, मार्ग, सटीक नियंत्रण और इसके पीछे के तर्क पर मैप करता है - और संपादन को `frontend`/`backend` को सौंप देता है। यह उस पर काम करता है जो पहले से मौजूद है (`screenshot` का उलटा)।
- ** अनुमान लगाने के बजाय सत्यापन करता है। ** यह स्क्रीनशॉट को साक्ष्य के रूप में मानता है, आधिकारिक डोमेन और दस्तावेज़ों की पुष्टि करता है, वर्तमान साइट डेटा की जांच करता है, और संभावित फ़िशिंग या पुराने मानों को चिह्नित करता है।
- **`i18n` "शून्य भाषा हार्डकोडिंग" लागू करता है। ** एजेंट पहले पता लगाते हैं कि कोई प्रोजेक्ट बहुभाषी है या नहीं और अनुकूलन करते हैं - उपयोगकर्ता-सामना करने वाली स्ट्रिंग एक अनुवाद परत (नेक्स्ट-इंटल / रिएक्ट-आई18नेक्स्ट / आई18नेक्स्ट) से गुजरती हैं, कभी इनलाइन नहीं।

## कॉन्फ़िगरेशन (MCP और कुंजियाँ)

पैकेज में **कोई रिमोट बैकएंड या डेटाबेस** नहीं है। वैकल्पिक लाइवबोर्ड एक लोकलहोस्ट-ओनली इन-मेमोरी प्रक्रिया है। MCP सर्वरों को टोकन की आवश्यकता होती है, और **प्रत्येक उपयोगकर्ता अपना स्वयं का टोकन प्रदान करता है**। इस कार्य को **Claude Code, Codex, Cursor और Kimi CLI** में समान रूप से करने के लिए - और चाहे आप टर्मिनल से लॉन्च करें या डॉक / स्पॉटलाइट / एक आईडीई से - प्रत्येक stdio MCP सर्वर को एक छोटे लॉन्चर (`bin/mcp-env.mjs`) के माध्यम से शुरू किया जाता है जो **एक फ़ाइल** से आपकी कुंजी पढ़ता है:

```
~/.config/agent-vorcl-flow/.env          # Windows: %APPDATA%\agent-vorcl-flow\.env
```

इंस्टॉलर इसे [`.env.example`](../.env.example) से बनाता है। इसे खोलें और केवल वही कुंजियाँ भरें जिनका आप उपयोग करते हैं:

```dotenv
ANTHROPIC_API_KEY=      # Task Master main provider: Claude
OPENAI_API_KEY=         # alternative main provider: GPT
PERPLEXITY_API_KEY=     # optional: Task Master research mode
FIRECRAWL_API_KEY=      # firecrawl web research
GITHUB_TOKEN=           # github MCP

# For the `database` agent — these point at YOUR project's DB, not the plugin's:
MONGODB_URI=            # mongodb://user:pass@host:27017/db
REDIS_URL=              # redis://host:6379
POSTGRES_URL=           # postgres://user:pass@host:5432/db
```

> ** `~/.zshrc` के बजाय एक लॉन्चर क्यों? ** Env-var का विस्तार प्रति रनटाइम (`${VAR:-}` में Claude, `${env:VAR}` में Cursor, Codex/Kimi में अक्षर) में भिन्न होता है और प्रत्येक रनटाइम केवल उस वातावरण को पढ़ता है ** इसे ** लॉन्च किया गया था। macOS पर GUI / IDE लॉन्च स्रोत `~/.zshrc` नहीं है, इसलिए निर्यात की गई कुंजियाँ अदृश्य हैं और सर्वर किसी भी चीज़ से कनेक्ट नहीं होते हैं - क्लासिक "MCP env सेट नहीं" विफलता। एक `.env`फ़ाइल से पढ़ने से दोनों समस्याएं एक साथ दूर हो जाती हैं।**प्राथमिकता** (बाद में जीतता है): प्रोजेक्ट रूट में साझा `~/.config/agent-vorcl-flow/.env` → ए `./.env` → आपके शेल में एक वास्तविक `export`। साझा फ़ाइल में वैश्विक कुंजियाँ रखें, एक प्रोजेक्ट `.env` के साथ प्रति-प्रोजेक्ट (उदाहरण के लिए एक अलग `MONGODB_URI`) को ओवरराइड करें, और एक वास्तविक शेल निर्यात अभी भी CLI रन के लिए जीतता है। आप लॉन्चर को `AGENT_VORCL_ENV_FILE=/path/.env` के साथ एक अलग फ़ाइल पर इंगित कर सकते हैं।

एक सर्वर जिसकी आवश्यक कुंजी गायब है, बस ** प्रारंभ नहीं होता है** - आपको रनटाइम के MCP लॉग में एक-पंक्ति `[agent-vorcl-flow] MCP «…» is not configured: …` दिखाई देगी, और हर दूसरा सर्वर काम करता रहेगा। `.env` में कुंजी जोड़ें और पुनरारंभ करें। (आप `GITHUB_TOKEN`/`MONGODB_URI` नाम रख सकते हैं - लॉन्चर उन्हें सर्वर द्वारा अपेक्षित `GITHUB_PERSONAL_ACCESS_TOKEN`/`MDB_MCP_CONNECTION_STRING` पर मैप करता है।)

> ⚠️ **एआई-संचालित Task Master कमांड के लिए आवश्यक:** कम से कम एक चयनित प्रदाता को कॉन्फ़िगर करें - `ANTHROPIC_API_KEY` के लिए `ANTHROPIC_API_KEY`, जीपीटी के लिए `OPENAI_API_KEY`, या Codex CLI OAuth। `.taskmaster/config.json` में चयनित मॉडल के क्रेडेंशियल के बिना, `/vorcl` कार्यों को उत्पन्न या विस्तारित नहीं कर सकता है।

चुनें कि कौन सा Task Master प्रदाता वास्तव में जनरेशन चलाता है; अकेले कुंजियाँ मॉडल का चयन नहीं करतीं:

```bash
/task-master:provider anthropic <model-id>   # Claude via ANTHROPIC_API_KEY
/task-master:provider openai <model-id>      # GPT via OPENAI_API_KEY
/task-master:provider codex-cli <model-id>   # ChatGPT OAuth via `codex login`
```

कमांड आधिकारिक `task-master models` प्रवाह का उपयोग करता है और केवल मॉडल चयन को `.taskmaster/config.json` में संग्रहीत करता है। `PERPLEXITY_API_KEY` वैकल्पिक है और इसकी आवश्यकता केवल तभी होती है जब पर्प्लेक्सिटी को अनुसंधान मॉडल के रूप में चुना जाता है।

रिमोट **वर्सेल** और **रेंडर** सर्वर OAuth का उपयोग करते हैं (ब्राउज़र में `/mcp` के साथ अधिकृत करें)। हेडलेस/CI में रेंडर करने के लिए, अपने वातावरण में `RENDER_API_KEY` सेट करें और अपने रनटाइम के लिए उस सर्वर पर एक बियरर हेडर प्रविष्टि जोड़ें।

इंस्टॉलर भूमिका परिभाषाओं को Cursor फ्रंटमैटर में परिवर्तित करता है, कौशल-नाम टकराव से बचने के लिए `avf-` के साथ उप-एजेंटों को जोड़ता है, `model: inherit` का उपयोग करता है, और केवल-ऑडिट एजेंटों को `readonly: true` के रूप में चिह्नित करता है। समान नाम वाली मौजूदा MCP सर्वर प्रविष्टियाँ संरक्षित हैं। देखें [`cursor/README.md`](../cursor/README.md).

## Kimi CLI

[Kimi CLI](https://github.com/MoonshotAI/kimi-cli) (मूनशॉटएआई) मूल रूप से एजेंट कौशल, कस्टम एजेंट फ़ाइलें और जीवनचक्र हुक लोड करता है; AVF Claude और Cursor द्वारा उपयोग किए जाने वाले उन्हीं MCP सर्वरों को भी मर्ज करता है:

| Agent-Vorcl-Flow अवधारणा | Kimi CLI समकक्ष |
| --- | --- |
| कौशल/कार्य आदेश | `~/.kimi/skills` और `/skill:<name>` |
| Expoकस्टम एजेंट | `kimi --agent-file ~/.kimi/agents/avf-expo-mobile.yaml` |
| Expo पोस्टटूलयूज़ गार्ड | `~/.kimi/config.toml` | में विलीन हो गया
| `.mcp.json` | `~/.kimi/mcp.json` | में मर्ज किए गए सर्वर
| प्रति-रनटाइम कुंजी फ़ाइल | साझा `~/.config/agent-vorcl-flow/.env` (लॉन्चर के माध्यम से) |

```bash
npx github:Vitammiin/agent-vorcl-flow --kimi
kimi mcp list          # verify connected servers
kimi mcp test github   # check a server's connection and tools
kimi --agent-file ~/.kimi/agents/avf-expo-mobile.yaml
```

Kimi CLI का `mcp.json` में कोई `${VAR}` विस्तार नहीं है, इसलिए कुंजी लॉन्चर के माध्यम से साझा `.env` से आती हैं - बिल्कुल अन्य रनटाइम की तरह। देखें [`kimi/README.md`](../kimi/README.md).

## परियोजना संरचना

```text
.claude-plugin/plugin.json      # plugin manifest
.claude-plugin/marketplace.json # local marketplace (for install)
agents/       24 sub-agent definitions (*.md)
skills/       <skill>/SKILL.md            (46 skills; some ship references, scripts, tests or HTML assets)
commands/     <namespace>/<command>.md    (150 commands, /namespace:command, including /vorcl and /audit)
hooks/        hooks.json + SessionStart + PostToolUse guards (empty catch, Expo architecture/UI boundaries)
.mcp.json     github, filesystem, postgres, mongodb, redis, docker, firecrawl, vercel, render, task-master, mermaid
.env.example  template for ~/.config/agent-vorcl-flow/.env (single key file for all runtimes)
translations/ localized README files (21 translations)
bin/          install.mjs (the npx installer) + mcp-env.mjs (cross-runtime MCP launcher / .env loader)
codex/        GPT Codex adapter (skills + config.toml + install.sh)
cursor/       Cursor adapter (MCP template + installation notes)
kimi/         Kimi CLI adapter (skills install + Expo agent/hook + MCP)
```

**यह एक साथ कैसे फिट बैठता है:** `agents/*.md` एक भूमिका घोषित करें और, सामने वाले `skills:` में, कौशल संलग्न करें → `skills/*/SKILL.md` में कौशल विवरण द्वारा ऑटो-लोड किए जाते हैं → `commands/<agent>/*.md` त्वरित `/agent:command` शॉर्टकट प्रदान करते हैं जो उप-एजेंट को सौंपते हैं → `.mcp.json` एजेंटों को उनके उपकरण देता है, प्रत्येक `bin/mcp-env.mjs` के माध्यम से शुरू होता है जो साझा `.env` से रहस्यों को लोड करता है। एक `SessionStart` हुक बताता है Claude एजेंट उपलब्ध हैं।
