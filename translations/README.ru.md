# Agent-Vorcl-Flow

Инженерные роли, навыки и независимая проверка для Claude Code, Codex, Cursor и Kimi CLI. AVF использует инструменты текущей сессии. Ваши MCP-подключения, ключи, модели и система задач остаются под вашим управлением.

## Установка

Нужны Node.js 20 или новее и поддерживаемый клиент. Выберите клиент явно: запуск без аргументов только показывает справку.

```bash
node bin/install.mjs --help
node bin/install.mjs --codex --dry-run
node bin/install.mjs --codex
```

Для другого клиента используйте `--claude`, `--cursor` или `--kimi`; `--all` явно выбирает все четыре. При установке с GitHub/npm используйте тот же флаг адаптера:

```bash
npx github:Vitammiin/agent-vorcl-flow --codex
npx --yes agent-vorcl-flow@latest --codex
```

Эти команды получают версию из удалённого репозитория/пакета. Для ещё не опубликованных правок используйте локальный установщик выше.

| Клиент | Что устанавливается | Каталог по умолчанию |
| --- | --- | --- |
| Claude Code | Skills и агенты `avf-*` | `~/.claude/skills`, `~/.claude/agents` |
| Codex | Skills | `~/.agents/skills` |
| Cursor | Skills и агенты `avf-*` | `~/.cursor/skills`, `~/.cursor/agents` |
| Kimi CLI | Skills и агенты `avf-*` | `~/.kimi/skills`, `~/.kimi/agents` |

Установщик записывает принадлежность компонентов в `.agent-vorcl-flow-install.json` рядом с ними. Обновление допустимо, только если хеш всего дерева компонента совпадает с записанным. Существующие компоненты без записи владения, локальные изменения и символические ссылки сохраняются. Обратите внимание на сообщения `Preserved:`: старый конфликтующий skill может оставаться активным до ручного разрешения. Для обновления повторите ту же команду.

Абсолютные пути можно задать через `CLAUDE_HOME`, `AVF_SKILLS_DIR` (skills Codex), `CURSOR_HOME`, `KIMI_HOME`. `CODEX_HOME` используется только при поиске старой конфигурации. Установка не меняет `AGENTS.md`, настройки клиента, MCP, профили моделей, env-файлы, сервисы или данные Task Master; не устанавливает hooks и не вызывает другие CLI.

## Использование

Откройте входной skill через штатный интерфейс клиента. Примеры для Codex:

```text
$vorcl add a shopping cart and verify checkout
$audit .
$init-code .
$backend-refactor simplify invoice validation
```

Отдельно подключаемый Claude-плагин предоставляет `/vorcl`, `/audit .`, `/backend:refactor`; локальный установщик добавляет соответствующие skills и агентов. Если клиенту требуется перезапуск для обнаружения новых навыков, перезапустите его.

`vorcl` сопоставляет цель с файлами проекта, выбирает одну ведущую роль и загружает только нужные навыки. Исполнитель вносит изменения, отдельный проверяющий сверяет согласованные критерии приёмки. Завершение сопровождается результатами проверки и ограничениями.

По умолчанию план находится в текущей сессии. Аудит в режиме report-only не создаёт задачи, не меняет продукт и сам не переключается на исправления. `init-code` создаёт описание только по запросу. Если `PROJECT_DESCRIPTION.md` уже существует, изменяющая роль проверяет влияние и обновляет только разделы с существенными изменениями контекста.

## Инструменты и задачи

AVF не поставляет активных регистраций MCP-серверов. Пустые MCP-файлы адаптеров оставлены для совместимости. Подключайте MCP в своём клиенте со своими именами серверов, версиями, аккаунтами и ключами. Skills используют доступные возможности сессии и не предполагают наличие определённого MCP namespace.

Task Master опционален. Для постоянного учёта задач выберите его явно, используя уже настроенное подключение или CLI. Наличие `.taskmaster` или доступного инструмента само по себе не разрешает инициализацию, смену провайдера/моделей, установку пакетов или переписывание настроек. Без выбранного трекера реализация продолжается по плану сессии.

При выборе трекера сохраняйте только ID текущей цели, учитывайте выбранный проект/tag, захватывайте задачу перед работой и завершайте после независимой проверки. Не берите чужие задачи из общего backlog. Файлы координации AVF находятся в `.agent-vorcl/` отдельно от данных трекера. Подробнее: [workflow](../skills/workflow/SKILL.md), [адаптер Task Master](../skills/task-master/SKILL.md).

## Переход со старого установщика

Старые версии добавляли MCP, профили моделей, общий файл ключей, hooks, а некоторые — автозапускаемый runtime. Новый установщик сохраняет существующие настройки: обновление исходников не отменяет прежнюю установку на машине.

```bash
node bin/install.mjs --check-legacy
node bin/install.mjs --codex --dry-run
```

Первая команда показывает узнаваемые пути старой установки, не печатая значения настроек. Сделайте резервную копию настроек клиента, проверьте только записи AVF и сохраните собственные MCP и данные Task Master. Неизвестная принадлежность не даёт разрешения на удаление. Подробный порядок проверки и отката — в [миграции](../docs/MIGRATION.md).

Старые skills без нового реестра владения намеренно сохраняются. Сравните их с новыми исходниками, сохраните копии заменяемых версий и разрешите конкретные коллизии. Совпадение имени не считается доказательством принадлежности.

## Архитектура

| Слой | Ответственность | Источник |
| --- | --- | --- |
| Реестр ролей | Владение и маршрутизация | `scripts/roles.json` |
| Промпты агентов и команд | Поведение ролей и отдельные задачи | `agents/`, `commands/` |
| Доменные skills | Знания, скрипты и справочные материалы | `skills/` |
| Генерируемые промпты Codex | Входные skills клиента | `codex/skills/` |
| Локальный установщик | Копирование и обновление своих компонентов | `bin/install.mjs` |
| Необязательный экспериментальный runtime | Локальные запуски, результаты, маршрутизация | `src/`, `bin/runtime.mjs` |

Генерируемые промпты проверяются по каноническим источникам. Установщик добавляет ресурсы skills без дублирования этих файлов в опубликованном зеркале Codex. Выполнение команд, настройки подключений и пользовательские разрешения принадлежат клиенту. AVF не заменяет эти механизмы.

Экспериментальный runtime запускается отдельно вручную. Он не нужен установленным ролям, не регистрируется в клиенте, не читает и не обновляет Task Master. Его состояние — `.agent-vorcl/runtime/`. Подробнее: [ограничения и запуск](../docs/RUNTIME_V3.md), [архитектурный разбор](../docs/ARCHITECTURE_REVIEW.md).

## Разработка и проверка

```bash
npm ci
npm test
npm run test:registry
npm run test:package
AVF_E2E_NETWORK=1 npm run runtime:test
```

Последняя команда включает интеграционный HTTP-тест через loopback и требует разрешения открыть локальный порт. Остальные тесты работают с fixtures и временными домашними каталогами. Проверяется сохранение настроек и компонентов пользователя, повторяемость установки и отсутствие записей при просмотре справки. Runtime-тесты проверяют конкуренцию, изоляцию Task Master и результаты проверки.

```bash
npm run generate:roles
npm run generate:codex
npm run generate:capabilities
npm run docs:locales:generate
```

Полные руководства поддерживаются на английском и русском. Остальные языковые страницы содержат локализованные ссылки на актуальное руководство и не выдаются за полные синхронные переводы. Генерация локалей детерминирована и не использует сеть. Тесты не публикуют пакет и не устанавливают его в настоящий клиент.
