Грамотно расставь/выправи логи на границе ошибки: **$ARGUMENTS**.

Если нет root Pino, модули создают свой `pino()`, нет `requestId`/`redact` или логи уходят HTTP в Loki — делегируй `/logging:update` и роль `logging`.

Структурные логи (JSON: pino/структурный logger), не голый `console.log` в проде. **Уровни:** `error` — сбой, требующий внимания; `warn` — аномалия с фолбэком; `info` — бизнес-события/границы запроса; `debug` — диагностика (в проде выкл./по флагу). **Логируй один раз** — на слое, где ошибка обрабатывается и есть контекст; если ошибку пробрасывают выше — здесь не логируй (убери дубли на каждом уровне). Добавляй поля: операция, ключевые id, `requestId`/correlation id, длительность важных операций, ошибку целиком (`stack`+`cause`). **Никогда не логируй** пароли, токены, ключи, PII, полные чувствительные payload'ы — маскируй; на горячих путях сэмплируй. Логи не используй для управления потоком. После правок **докажи, что поведение не изменилось**: прогони затронутые тесты и/или запусти код — поменялись только логи; покажи образец вывода (уровни верные, секретов/PII в строках нет). Опирайся на навыки `error-handling`, `nodejs`, `backend-architecture`, `react`. Делегируй субагенту `resilience`.
