Грамотно покрой код обработкой ошибок и логами: **$ARGUMENTS**.

Ставь `try/catch` **на границах** (I/O, внешние API, `JSON.parse`/zod, транзакции, места с cleanup) — не вокруг каждой строки; программные баги пусть всплывают до глобального обработчика. В каждом `catch` — одно из трёх: обработать + залогировать, пробросить (`throw new AppError(msg, { cause: error })`), либо преобразовать в доменную ошибку; **пустой `catch {}` недопустим**. В TS `catch (e: unknown)` — сузь тип. Ресурсы освобождай в `finally`. Для транзиентных внешних вызовов — таймаут (`AbortSignal.timeout`) + идемпотентный ретрай с бэкоффом.

Логи расставляй грамотно: структурные (уровни `error`/`warn`/`info`/`debug`), **один раз** на границе обработки (пробрасываешь — не логируй тут), с контекстом/`requestId`, целиком ошибку (`stack`+`cause`), **без секретов/PII/токенов**. После обёртывания **докажи, что поведение не изменилось**: прогони затронутые тесты и/или запусти код и покажи вывод — те же результаты и статусы на happy-path; обработка ошибок не должна менять логику. Красный прогон — чини до зелёного, не сдавай. Опирайся на навыки `error-handling`, `nodejs`, `typescript`, `backend-architecture`, `react`. Делегируй субагенту `resilience`.
