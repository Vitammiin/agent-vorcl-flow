Проведи **read-only** аудит git-истории: **$ARGUMENTS**.

Ничего не правь, не коммить, не удаляй — только найди и оформи находки.

1. **Конвенция сообщений:** `git log --pretty='%h %s' --no-merges` — сообщения вне `тип(scope): суть` («wip», «fixes», «финал2»), смешение языков, breaking без `!`/футера.
2. **Коммиты-свалки:** `git log --stat --no-merges` — гигантские коммиты (десятки файлов из разных областей за раз), смешение feat+fix+chore в одном; они ломают ревью, bisect и changelog.
3. **Большие бинарники:** `git rev-list --objects --all | git cat-file --batch-check='%(objecttype) %(objectname) %(objectsize) %(rest)' | awk '$1=="blob" && $3>1000000'` — блобы >1 МБ в истории (артефакты сборки, изображения, дампы), кандидаты в LFS/`.gitignore`.
4. **Ветки-сироты:** `git branch -a --no-merged` + `git for-each-ref --sort=-committerdate refs/heads --format='%(refname:short) %(committerdate:relative)'` — давно не обновлявшиеся невлитые ветки, следы брошенных worktree (`git worktree list`).
5. **Версии/теги:** совпадают ли последний тег и версии в манифестах (`package.json` и др.); есть ли коммиты после тега без записи в `[Unreleased]` changelog.

Формат находки: `commit/файл/ветка → что не так → чем грозит → конкретная починка`; severity `critical>high>medium>low`. Сводка — таблицей по категориям. По значимым находкам — `add_task` (Task Master); любые исправления (перепись истории, удаление веток) — деструктивны и выполняются отдельно только с явного подтверждения владельца.

Края: пустой `$ARGUMENTS` — аудить всю историю текущей ветки; мелкий репозиторий без тегов — отметь отсутствие релизной дисциплины как находку, а не ошибку.

Опирайся на навык `git-workflow`. Делегируй субагенту `gitflow`.
