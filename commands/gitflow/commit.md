description: Поимённый коммит по Conventional Commits — сам проверь git status, файлы явно, чужой WIP не трогать. Use when нужно закоммитить изменения (gitflow)
argument-hint: "[контекст задачи и/или файлы; пусто — коммит текущей работы]"
allowed-tools: Read, Bash, Grep, Glob
---

Закоммить изменения, относящиеся к задаче: **$ARGUMENTS**.

Контекст: рядом могут работать параллельные сессии — в каталоге возможен чужой незакоммиченный WIP, который нельзя захватить.

1. Сам выполни `git status --porcelain` и `git diff` — не доверяй пересказам о состоянии дерева.
2. Отбери ТОЛЬКО файлы, относящиеся к задаче из `$ARGUMENTS`. Незнакомые/несвязанные изменения — **стоп и спроси владельца**, в коммит не включай.
3. `git add <файл> <файл> …` — строго по именам. НИКОГДА `git add .` / `git add -A`.
4. Составь сообщение по Conventional Commits: `тип(scope): суть` (feat/fix/docs/refactor/perf/test/chore); breaking — `!` + футер `BREAKING CHANGE:`. Несвязанные правки — раздельными коммитами.
5. `git commit`, затем снова `git status` — покажи оба вывода: hash коммита и что чужой WIP остался нетронут.
6. НЕ пушь: push — отдельное действие только с явного подтверждения владельца.

Края: пустой `$ARGUMENTS` — восстанови задачу по `git diff` и предложи разбивку на коммиты до выполнения; пустое дерево (`git status` чист) — так и скажи, ничего не выдумывай.

Опирайся на навык `git-workflow`. Делегируй субагенту `gitflow`.
