Найди в существующем коде экран/компонент со скриншота: **$ARGUMENTS**.

Сначала подтверди, что это **существующий проект** (кодовая база есть, якоря грепаются); если это генерация нового UI — перенаправь на `/screenshot:convert`.

Открой изображение через Read и извлеки **якоря для поиска**: видимый текст (заголовки, лейблы кнопок, плейсхолдеры, пункты меню, тосты), иконки, тип блока (таблица/карточки/форма/табы), контекст маршрута. Ищи `rg` от самой редкой строки к частой; в мультиязычном проекте текст на экране — это **значение перевода**: грепни его по файлам локали → получи ключ → грепни ключ по компонентам (см. `i18n`). Игнорируй `node_modules`/сборку. Много совпадений — сузь по соседним якорям; ноль — проверь склейку строк/шаблоны/`data-testid`/`aria-label`.

Отдай привязку с точностью до **`file:line`** + короткий фрагмент; при неоднозначности — список кандидатов с различающим признаком. **Только чтение** — ничего не создавай и не правь. Следующие шаги конвейера: маршрут — `/pinpoint:route`, контрол — `/pinpoint:control`, логика — `/pinpoint:trace`. Опирайся на навыки `ui-source-mapping`, `screenshot-to-code`, `frontend-architecture`, `react`, `nextjs`, `i18n`. Делегируй субагенту `pinpoint`.
