Построй Mermaid-диаграмму по описанию: **$ARGUMENTS**.

Выбери тип под задачу (если не задан): процесс/логика → **flowchart**, взаимодействие во времени → **sequenceDiagram**, модель данных → **erDiagram**, структура классов → **classDiagram**, состояния → **stateDiagram-v2**, план → **gantt**, доли → **pie**, ветки → **gitGraph**, идеи → **mindmap**, события → **timeline**.

Требования: точный заголовок первой строки (`flowchart TD`, не `lowchart`); осознанное направление (`TD`/`LR`); подписи со спецсимволами/скобками — в кавычки `["..."]`; парные `subgraph … end`; семантические цвета через `classDef` (роль → класс); не перегружай один граф. **Обязательно** прогони готовый `.mmd` через реальный рендер (`mcp-mermaid` MCP или `mmdc -i file.mmd -o file.svg`) и устрани ошибки парсера до выдачи — не отдавай непроверенное.

**Материализуй результат как файл(ы) в рабочем каталоге пользователя, в нужном формате** — `.mmd` плюс рендер (SVG/PNG/PDF, по запросу). Не оставляй диаграмму только в ответе или во временной `/tmp` — пользователю нужен готовый файл на руки. Отдай: **пути к файлам** + результат рендер-теста + как посмотреть (Mermaid Live Editor / VS Code preview / `mmdc`) + заметки о допущениях. Неоднозначное помечай и предлагай альтернативу. Опирайся на навыки `mermaid-diagrams`, `mermaid-rendering`, `system-design`. Делегируй субагенту `mermaid`.
