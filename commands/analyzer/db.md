Проверь структуру БД (**read-only**): **$ARGUMENTS**.

Проверяй ту СУБД(ы), что реально в проекте — реляционную и/или документную; ничего не изменяй в БД.

- **Postgres** — через MCP `postgres` / `query_render_postgres` выполняй **только read-only** SQL (SELECT/EXPLAIN, `information_schema`, `pg_indexes`): отсутствующие индексы под частые запросы, отсутствие FK/констрейнтов/NOT NULL/UNIQUE, потенциальные N+1 (в коде репозиториев), проблемы нормализации, рассинхрон схемы БД и моделей/миграций, небезопасные/необратимые миграции.
- **MongoDB** — через MCP `mongodb` (read-only; для аудита сервер поднимают с `--readOnly`): отсутствующие/неоптимальные индексы (`listIndexes`, compound/TTL), запросы со сканом коллекции — COLLSCAN (`explain`), несогласованность формы документов между записями, спорный выбор embedding vs referencing, N+1 без `$lookup`/populate, отсутствие schema-валидаторов, безграничный рост массивов/размера документа.

Формат: объект (`таблица`/`колонка` или `коллекция`/`поле`) или `file:line`, что нашли, первопричина, конкретная починка (DDL/индекс/миграция либо индекс/валидатор/реструктуризация документа); severity по влиянию. По значимым находкам — `add_task` (Task Master). Опирайся на навыки `database`, `postgresql`, `mongodb`. Делегируй субагенту `analyzer`.
