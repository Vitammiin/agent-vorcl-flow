Напиши unit-тесты для: **$ARGUMENTS**.

1. Определи раннер по `package.json` (`vitest`/`jest`/node:test) и конвенции проекта (`*.test.ts` рядом vs `__tests__/`) — следуй им, не навязывай Vitest Jest-проекту.
2. Прочитай код модуля, выпиши контракты: входы/выходы, границы, ожидаемые ошибки.
3. Покрой: happy path, граничные значения (пусто/0/max/unicode), ошибки (невалидный вход, отказ зависимости).
4. Мокай только границы I/O (сеть, БД, файлы, время, random); чистую доменную логику не мокай.
5. Структура AAA, одно логическое утверждение на тест, имена «что делает при каком условии».
6. Покажи, что тест умеет падать: прогони с намеренно сломанным ожиданием (или до фикса) — тест, который не падает никогда, ничего не проверяет.
7. Прогони: `npx vitest run <файл>` / `npx jest <файл>` — вставь вывод в ответ. Красный → чини до зелёного.

Край: пустой $ARGUMENTS — спроси файл/модуль; файла нет — покажи ближайших кандидатов через Glob и уточни.

Опирайся на навыки `testing-strategy`, `typescript`, `nodejs`. Делегируй субагенту `testing`.
