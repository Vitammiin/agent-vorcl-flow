Спланируй и подготовь безопасную миграцию: **$ARGUMENTS**.

Только **обратимые** миграции по схеме **expand → migrate/backfill → contract** (zero-downtime): сначала совместимое добавление, затем перелив данных батчами, затем удаление старого отдельным шагом. Большие таблицы — без долгих блокировок (`CREATE INDEX CONCURRENTLY`, батч-бэкфилл). Обязательно предусмотри `down`/откат. Покажи план (up/down, порядок, влияние на блокировки/время) до применения. **Применение миграции меняет данные необратимо — только с явным подтверждением человека**; неоднозначные «ок/давай» prod не авторизуют, необратимые активации выноси в PR. Первопричину чини схемой/кодом, а не точечной правкой записей. Опирайся на навыки `database`, `postgresql`, `mongodb`. Делегируй субагенту `database` (для доступа к прод-БД на Render — агенту `render`).
