Проверь изменения перед пушем (**read-only**): **$ARGUMENTS**.

1. Собери область: `git diff <база>...HEAD --name-only` + незакоммиченное (`git status --porcelain`); база по умолчанию — upstream текущей ветки (`@{u}`), при пустом **$ARGUMENTS** и без upstream — `origin/dev`. Нечего пушить — так и скажи.
2. **Секреты** в диффе: паттерны ключей (`sk-`, `ghp_`/`github_pat_`, `AKIA`, `xox.`, `rnd_`, `fc-`, `AIza`, `Bearer`, private keys, `user:pass@`) по `git diff <база>...HEAD` — именно по диффу, не по всему дереву; плюс новые `.env`-файлы вне `.gitignore`.
3. **Очевидные инъекции** в изменённых файлах: интерполяция ввода в SQL/shell (`exec`/`spawn` со строкой), `dangerouslySetInnerHTML`/`innerHTML` с данными, `eval`.
4. **PII:** реальные email/телефоны, личные пути `/Users/…`, внутренние hostname в добавленных строках.
5. Отфильтруй ложное (env-подстановки, плейсхолдеры, тестовые фейки) — проверь контекст каждой строки перед вердиктом.

Вердикт: **ЗЕЛЁНЫЙ** (пуш безопасен) или **КРАСНЫЙ** (пуш блокирован) — с доказательствами: список прогнанных проверок + для красного каждая находка `file:line` + цитата + severity + что сделать до пуша. Найденный реальный секрет — красный всегда: ротация ключа обязательна, даже если строку убрать из коммита. Ничего не правь; фиксы — исполнителям (`backend`/`frontend`/`gitflow`).

Опирайся на навыки `secrets-detection`, `security-audit`. Делегируй субагенту `security`.
