Создай или обнови README: **$ARGUMENTS**.

1. Изучи реальность, не память: `package.json` (name, `scripts`, `engines`), lock-файл (менеджер пакетов), структура каталогов, точки входа, `.env.example`. README описывает то, что есть в коде сейчас.
2. Структура (порядок из навыка `technical-writing`): лид-абзац «что это и зачем» (2–4 предложения, без маркетинговой воды) → Quickstart (минимум шагов до работающего результата) → Usage (основные сценарии с примерами) → Configuration (таблица env/опций: имя, тип, дефолт, назначение — из кода) → Troubleshooting (реальные частые ошибки) → лицензия.
3. **Каждый пример прогони** (Bash) или сверь со `scripts`; каждый флаг/env — грепом по коду. Пример должен работать копипастом; плейсхолдеры — явные `<...>`.
4. Счётчики и версии — из реальных файлов (`ls | wc -l`, `package.json`), не по памяти. Относительные ссылки — проверь существование целей (Glob).
5. Если есть README на других языках (`README.ru.md` и т.п.) — синхронизируй **паритет**: тот же набор секций, те же факты/примеры (команды не переводятся), взаимные ссылки-переключатели вверху. Канон — язык, который правится первым.

Края: пустой **$ARGUMENTS** — корневой `README.md`; существующий README не переписывай стилистически без запроса — чини дрейф и дополняй недостающие секции.

Отдай путь к файлу + доказательства проверки примеров (вывод команд/греп-сверки) + статус паритета. Опирайся на навык `technical-writing`. Делегируй субагенту `docs`.
