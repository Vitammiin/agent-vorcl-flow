Сгенерируй `docs/API.md` из OpenAPI-спеки: **$ARGUMENTS**.

1. Найди спеку: статическая `openapi.{yaml,json}`, рантайм-эндпоинт стека (`/documentation/json` · `/api-json` · `/openapi.json` · `/v3/api-docs`) или генератор — эвристики поиска под стек в навыке `swagger-coverage`.
2. **Если спеки нет — не выдумывай API по коду.** Останови работу и предложи сначала `/swagger:audit` → `/swagger:cover` (агент `swagger` создаёт спеку — источник истины); документировать нечего, пока контракта нет.
3. Сводная таблица эндпоинтов: метод, путь, `summary`, auth (из `security`), теги — сгруппируй по тегам/модулям.
4. По каждой операции: параметры (`path`/`query`/`header`), `requestBody`, `responses` по кодам со схемами и Error-компонентом — **только из спеки**, ничего от себя.
5. curl-примеры на ключевые операции: реальные поля из схем, плейсхолдеры `<TOKEN>`/`<ID>`, базовый URL из `servers`; синтаксис каждого примера проверь (`bash -n`).
6. Версию API возьми из `info.version`; в шапке `docs/API.md` укажи источник спеки и дату генерации — чтобы дрейф был виден.

Края: пустой **$ARGUMENTS** — вся спека; задан модуль/тег — только его операции, не трогая остальное.

Отдай путь к `docs/API.md` + источник спеки + число задокументированных операций (сверь с числом операций в спеке). Опирайся на навыки `api-design`, `swagger-coverage`, `technical-writing`. Делегируй субагенту `docs`.
