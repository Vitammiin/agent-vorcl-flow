Найди дрейф документации относительно кода (**read-only**): **$ARGUMENTS**.

1. Собери корпус доков: `README*`, `docs/**`, `ARCHITECTURE.md`, `CONTRIBUTING.md`, `CHANGELOG.md` (Glob по `**/*.md`, минус `node_modules`).
2. Ссылки: относительные — проверь существование файлов и якорей (Glob/чтение заголовков); битый путь = находка. Внешние — проверь хотя бы формат/очевидные опечатки.
3. Примеры: каждую команду сверь со `scripts` в `package.json` и реальными бинарями (`npm run <x>` существует?); каждый флаг/env/эндпоинт из доки — грепом по коду; фрагменты кода — с текущими сигнатурами/именами файлов.
4. Счётчики и версии: «N агентов/модулей/команд» — пересчитай реальные файлы; номера версий — против `package.json`/манифеста/тегов; версии Node — против `engines`.
5. API-факты в доках — против OpenAPI-спеки (если спеки нет, отметь это как отдельную находку и предложи `/swagger:audit`).
6. Языковой паритет: `README.md` vs `README.ru.md` и прочие пары — одинаковый набор секций? совпадают факты/версии/примеры? Расхождения — с указанием секций.

**Ничего не правь.** Формат находки: `file:line` — что заявлено — что в реальности (доказательство: греп/вывод) — severity (`critical > high > medium > low`; врущий пример/битый quickstart = high+). По значимым находкам — `add_task` (Task Master).

Края: пустой **$ARGUMENTS** — весь корпус *.md проекта.

В конце — сводка дрейфа по документам (чисто/дрейф/сильно устарел) и заведённые задачи. Опирайся на навык `technical-writing`. Делегируй субагенту `docs` (только чтение).
