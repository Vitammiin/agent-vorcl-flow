Создай или обнови `CONTRIBUTING.md`: **$ARGUMENTS**.

1. Setup — из реальности: версия Node из `engines`, менеджер пакетов по lock-файлу (`package-lock.json`/`pnpm-lock.yaml`/`yarn.lock`), env — по `.env.example`. **Каждый шаг setup прогони** (Bash) или сверь со `scripts` — читатель должен пройти его копипастом.
2. Структура проекта — короткое дерево реальных каталогов с назначением каждого (сверь с `ls`, не по памяти); для деталей сошлись на `ARCHITECTURE.md`, не дублируй.
3. Тесты и проверки: реальные команды из `scripts` (`test`/`lint`/`typecheck`/`build`) — убедись, что они существуют, и покажи, чем подтверждается зелёное состояние перед PR.
4. Конвенции коммитов и веток — согласуй с фактической историей (`git log --oneline -20`) и gitflow-процессом проекта (агент `gitflow` — источник истины по веткам/релизам). Не навязывай Conventional Commits, если история им не следует: зафиксируй реальный стиль, переход предлагай отдельным решением.
5. PR-процесс: из какой ветки в какую, чек-лист перед PR (тесты, lint, доки обновлены), как проходит ревью, merge-стратегия — по фактическому процессу репозитория, не по учебнику.

Края: пустой **$ARGUMENTS** — корневой `CONTRIBUTING.md`; существующий файл — обновляй дрейф, не ломая принятые правила без обсуждения.

Отдай путь к файлу + доказательства (вывод прогнанных setup/test-команд, фрагмент `git log`, по которому выведены конвенции). Опирайся на навык `technical-writing`. Делегируй субагенту `docs`.
