# Задача: наладить мониторинг сервиса

Наладь наблюдаемость (см. `$docker`, `$nodejs`, `$backend-architecture`).

1. Оцени текущее: чем логирует (`console.log` vs pino/winston), есть ли health-эндпоинт, что в `HEALTHCHECK`/health-check хостинга.
2. Структурные логи: pino → JSON в stdout (контейнерная норма, без файлов в контейнере); уровни осознанно; контекст полями (`requestId`, длительность); секреты/PII — под запретом (redact-листы).
3. Health: `GET /health` — liveness (200 без внешних зависимостей); при нуждах `/ready` — readiness (коннект к БД/Redis с таймаутом). Подключи в `HEALTHCHECK` Dockerfile/compose и health-check хостинга.
4. Алерты (минимум): доля 5xx, p95 латентность, рестарты/OOM, ошибки коннекта к БД, диск/память — для каждого где смотреть сигнал.
5. На Render метрики/логи/наблюдение живого сервиса — делегируй роли `$render`.
6. Докажи: подними сервис, покажи `curl -s localhost:PORT/health` и пример JSON-строки лога.

Сервис не поднимается — сначала первопричина, не мониторинг поверх сломанного. Отдай изменённые файлы + вывод curl + пример лога + список алертов.
