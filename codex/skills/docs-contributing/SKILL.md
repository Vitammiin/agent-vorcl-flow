# Задача: создать/обновить CONTRIBUTING.md

Создай или обнови `CONTRIBUTING.md` (см. `$technical-writing`).

1. Setup — из реальности: Node из `engines`, менеджер пакетов по lock-файлу, env — по `.env.example`. **Каждый шаг прогони** или сверь со `scripts` — читатель проходит его копипастом.
2. Структура проекта — короткое дерево реальных каталогов с назначением (сверь с `ls`); детали — ссылкой на `ARCHITECTURE.md`, не дублируй.
3. Тесты и проверки: реальные команды из `scripts` (`test`/`lint`/`typecheck`) — убедись, что существуют; чем подтверждается зелёное состояние перед PR.
4. Конвенции коммитов/веток — из фактической истории (`git log --oneline -20`) и gitflow-процесса проекта (роль gitflow). Не навязывай Conventional Commits, если история им не следует, — зафиксируй реальный стиль.
5. PR-процесс: из какой ветки в какую, чек-лист перед PR, ревью, merge-стратегия — по фактическому процессу репозитория.

Отдай путь к файлу + доказательства (вывод прогнанных команд, фрагмент `git log`, по которому выведены конвенции).
