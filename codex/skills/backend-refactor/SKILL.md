# Задача: рефакторинг

Отрефактори код, который предоставил пользователь, сохранив поведение.

Рефакторинг меняет структуру, не поведение: внешние контракты (HTTP-ответы, сигнатуры, побочные эффекты) остаются прежними, и это доказывается тестами до и после.

1. Зафиксируй базовую линию: прогони существующие тесты и сохрани вывод; если тестов нет — сначала напиши характеризационные тесты на текущее поведение, до любых правок.
2. Найди, что улучшать: логика в контроллерах → в `service`, работа с БД → в `repository` (слои из `$backend-architecture`), дублирование, длинные функции, магические значения.
3. Рефактори малыми шагами: одно улучшение → прогон тестов → следующее; не смешивай перестановку кода с изменением логики в одном шаге.
4. Доказательство: зелёный вывод того же набора тестов, что в шаге 1, плюс diff до/после с пояснением, что и почему улучшено. Самоотчёт «должно работать» не принимается.

Если область не указана — спроси файл/модуль или предложи кандидатов по свежему diff. Если код не Node/TypeScript-бэкенд — скажи честно и применяй общие принципы рефакторинга без стеко-специфичных советов.

Опирайся на `$nodejs`, `$typescript`, `$backend-architecture`.
