# Задача: аудит дрейфа документации

Найди дрейф доков относительно кода (**read-only**, см. `$technical-writing`).

1. Корпус: `README*`, `docs/**`, `ARCHITECTURE.md`, `CONTRIBUTING.md`, `CHANGELOG.md` (все `*.md`, минус `node_modules`).
2. Ссылки: относительные — существование файлов/якорей; внешние — хотя бы формат.
3. Примеры: команды — против `scripts`/бинарей (`npm run <x>` существует?); флаги/env/эндпоинты — грепом по коду; фрагменты кода — с текущими сигнатурами.
4. Счётчики и версии: «N модулей» — пересчётом файлов; версии — против `package.json`/манифеста/тегов; Node — против `engines`.
5. API-факты — против OpenAPI-спеки (спеки нет — отдельная находка, предложи `$swagger-audit`).
6. Языковой паритет (`README.md` vs `README.ru.md`): набор секций, факты/версии, идентичность кодовых блоков.

**Ничего не правь.** Формат находки: `file:line` — заявлено — в реальности (доказательство: греп/вывод) — severity (`critical>high>medium>low`; врущий quickstart = high+). По значимым — `add_task`. В конце — сводка дрейфа по документам (чисто/дрейф/сильно устарел).
