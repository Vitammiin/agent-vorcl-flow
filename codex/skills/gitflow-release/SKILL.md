# Задача: выпустить релиз

Подготовь и выпусти релиз (см. `$git-workflow`).

1. Версия по semver из коммитов с последнего тега: `BREAKING CHANGE`/`!` → major; `feat` → minor; иначе patch. Покажи, какие коммиты дали бамп.
2. Синхронизируй версию во ВСЕХ манифестах (`package.json` и др. — найди grep'ом по текущей версии): тег = версии манифестов, иначе релиз невоспроизводим.
3. Обнови `CHANGELOG.md` (по `$gitflow-changelog`): `[Unreleased]` → `## [X.Y.Z] - <дата>`.
4. Закоммить релизные файлы поимённо (`chore(release): vX.Y.Z`), поставь `git tag vX.Y.Z`; покажи `git status` и `git log --oneline -3`.
5. **СТОП.** Покажи план публикации и жди явного «да»; односложное «ок» — не авторизация. Только после: `git push && git push origin vX.Y.Z`, затем `gh release create vX.Y.Z --notes-file <notes>` (или GitHub MCP). Отдай URL. Нет gh/MCP — отдай notes для ручной публикации, пометив.

Края: нет коммитов с последнего тега — релизить нечего; дерево грязное чужими правками — стоп и спроси.
