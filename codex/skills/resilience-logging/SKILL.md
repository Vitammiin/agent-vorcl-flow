# Задача: грамотное логирование (resilience)

Расставь/выправи логи на границе ошибки (см. `$error-handling`). Полный Pino-пакет — `$logging-update` / `$pino-logging`.

Структурные логи (JSON: pino/структурный logger), не голый `console.log` в проде. **Уровни:** `error` — сбой, требующий внимания; `warn` — аномалия с фолбэком; `info` — бизнес-события/границы запроса; `debug` — диагностика (в проде выкл./по флагу). **Логируй один раз** — на слое, где ошибка обрабатывается и есть контекст; пробрасывают выше — здесь не логируй (убери дубли). Поля: операция, ключевые id, `requestId`/correlation id, длительность важных операций, ошибка целиком (`stack`+`cause`). **Никогда** — пароли/токены/ключи/PII/полные чувствительные payload'ы (маскируй); на горячих путях сэмплируй. Логи не для управления потоком. После правок **докажи, что поведение не изменилось**: прогони затронутые тесты и/или запусти код — поменялись только логи; покажи образец вывода (уровни верные, секретов/PII в строках нет). Опирайся на `$error-handling`, `$nodejs`, `$backend-architecture`, `$react`.
