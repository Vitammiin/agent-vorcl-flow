# Задача: ревью архитектуры

Проведи ревью архитектуры, которую предоставил пользователь.

Ревью — read-only: код не правишь, а выдаёшь приоритизированный список проблем с доказательствами из кода (file:line), не мнений.

1. Построй карту фактической архитектуры: слои, модули, зависимости (поиск по импортам). Фиксируй то, что есть в коде, а не то, что декларировано в доках.
2. Найди нарушения границ: логика в контроллерах, обход слоёв, циклические зависимости, дублирование — каждое с конкретным `file:line`.
3. Проверь узкие места: N+1, синхронные вызовы там, где нужна очередь, единые точки отказа, места без горизонтального масштабирования.
4. Оцени нефункциональное: безопасность (auth/валидация на границах), наблюдаемость (логи, обработка ошибок), тестируемость (можно ли покрыть слой изолированно).
5. Приоритизируй: таблица «проблема → доказательство (`file:line`) → влияние → усилие → рекомендация», сверху критичное; в конце — 3 первых шага исправления.

Если область не указана — спроси, какой участок ревьюим, или возьми корень текущего проекта. Если фактический стек отличается от ожидаемого — скажи честно и адаптируй критерии под реальный стек, не натягивай чужие конвенции.

Опирайся на `$system-design`.
