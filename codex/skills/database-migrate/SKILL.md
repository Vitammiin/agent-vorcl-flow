# Задача: безопасная миграция (database)

Спланируй и подготовь миграцию (см. `$database`).

Только **обратимые** миграции по схеме **expand → migrate/backfill → contract** (zero-downtime): сначала совместимое добавление, затем перелив данных батчами, затем удаление старого отдельным шагом. Большие таблицы — без долгих блокировок (`CREATE INDEX CONCURRENTLY`, батч-бэкфилл). Всегда предусмотри `down`/откат.

1. Изучи текущую схему (read-only через MCP) и код миграций; напиши миграцию (up/down).
2. **Покажи план изменений**: DDL, порядок шагов, оценка влияния — какие блокировки и на сколько, ожидаемое время, обратимость (что делает `down`).
3. **Дождись ЯВНОГО подтверждения человека** — слова вроде «да, применяй»; молчание или «ок» на другой вопрос — НЕ подтверждение. Для prod необратимые активации выноси в PR.
4. Применяй, затем **проверь результат и покажи доказательство**: схема после (`information_schema`/`listCollections`), статус миграции, `EXPLAIN` затронутых запросов, что `down` существует и валиден.

Первопричину чини схемой/кодом, а не точечной правкой записей. Опирайся на `$database`, `$postgresql`, `$mongodb`. Для доступа к прод-БД на Render — роль `$render`.
