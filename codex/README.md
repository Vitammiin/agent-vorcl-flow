# Agent-Vorcl-Flow для Codex

Адаптер устанавливает роли, задачи и доменные навыки в `~/.agents/skills`. Каждый навык содержит необходимые локальные scripts и references. Глобальные `AGENTS.md`, `config.toml`, модели, профили и MCP остаются под управлением пользователя.

```bash
npx github:Vitammiin/agent-vorcl-flow --codex --dry-run
npx github:Vitammiin/agent-vorcl-flow --codex
```

Из checkout можно выполнить `bash codex/scripts/install.sh`; дополнительные флаги, например `--dry-run`, передаются тому же установщику. Абсолютный `AVF_SKILLS_DIR` меняет каталог skills. Без флагов основной установщик показывает справку; `--all` явно выбирает все адаптеры.

После установки откройте новый чат. Примеры:

```text
$vorcl добавить корзину в checkout
$backend-create-api POST /invoices
$frontend-create-component список заказов
$analyzer-audit
$testing-verify проверить выполненное изменение
```

Workflow ведёт план и результаты в текущем чате. Task Master используется только по явному выбору пользователя и через уже доступные инструменты. Установщик не подключает MCP, не создаёт shared env, не меняет настройки и не запускает hooks или сервисы.

`codex/AGENTS.md` — справочный пример маршрутизации, который можно изучить и адаптировать вручную. Он не добавляется в глобальный контекст автоматически. `codex/config.toml` не содержит профилей или серверов. Нативный plugin manifest `.codex-plugin/plugin.json` также не регистрирует MCP.

Повторная установка обновляет только неизменённые компоненты, записанные в `.agent-vorcl-flow-install.json`. Чужие навыки, пользовательские изменения и старые установки без реестра владения сохраняются целиком.

```bash
npx github:Vitammiin/agent-vorcl-flow --check-legacy
```

Проверка сообщает пути возможных старых конфигураций, не печатая их значения и не изменяя файлы. Дальнейшие действия — в [руководстве по миграции](../docs/MIGRATION.md).
